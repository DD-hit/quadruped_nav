# 真机接入边界

目标是复用同一套导航核心部署到真机。仿真和真机只替换外部数据提供者与速度接收者，不替换全局规划、局部规划和任务接口。

## 真机需要提供

- 已定位的机身里程计、注册点云，以及时间一致的 TF。
- 消费机身坐标系 `/cmd_vel` 的 D1 SDK 适配器，包含驱动端指令超时停车。
- 与真实机器人一致的外廓、安装关系、速度能力和到达容差参数。

当前 navigation.yaml 是可运行的原生参数示例，不是 D1 真机标定结果。SCAN 默认使用双圆柱模型，半径 0.25 m、前后偏移 0.18 m；全局半径 0.43 m 来自二者之和，保证两者示例外廓一致。实际机身及机械臂外廓需要替换为适用参数，不再叠加独立的逐连杆否决层。

SCAN 的 grid_map.ground_height 用作局部网格 Z 起点；示例设为 -2.5 m，以覆盖机身原点为零时的负高度地面。地面路径与机身轨迹的高度关系由接口层衔接，不将此值当作雷达安装高度。

## 仍未验证的内容

D1 SDK 机身参考点与模型 base_link 的关系仍待核对。现有雷达外参是名义 CAD 装配值，不代表实物标定。相关原始参数保留在 quadruped_bringup/config/robots/d1_edu.yaml。

当前仅完成理想外部 ROS 输入下的组合与接口验证。不能据此宣称完成 D1 真机导航、机械臂避碰或真实制动能力验收。

服务器的 DDS 回环传输配置属于运行环境，不是算法依赖。真机跨设备接入时需选择对应网卡及 DDS 配置，不能照搬本机回环配置。导航入口本身不会强制绑定该配置。
