# 运动地图定位检查

结论：已有完整导航演示中，正确初始化后，运动中的地图定位保持稳定，没有观察到持续累积的大幅偏移。但这是单次仿真记录复核，尚不能代表真机或任意场景。

数据为 2026-11-12 的成功完整演示：约 156 s、物理路径长 18.64 m，包含 1 个单点和 3 个连续目标。本轮没有重新运行导航，没有修改生产算法。

- 总计 299 次配准接受，0 次配准拒绝、0 次结果丢弃；初始化后的已记录状态保持 tracking。
- 匹配 RMSE 平均约 3.41 cm，最大约 3.51 cm。这是点云对应点残差，不是机器人定位误差，不能单独证明定位正确。
- 用固定历史地图基准将物理真值转换到 map，没有拟合额外轨迹对齐。共有 1,491 个已定位机身样本。
- 按回调时钟估算：运动时水平位置误差平均约 4.14 cm、P95 约 5.94 cm、最大约 6.46 cm；全部样本最大约 6.60 cm。运动偏航误差 P95 约 0.77°。
- 记录没有保存 body_pose 的原始消息时间戳，因此上述是近似值，不是严格同步定位精度。另检查 0、0.05、0.1、0.2 s 的假设延迟，运动位置误差 P95 约 5.8–7.8 cm、最大约 6.4–9.6 cm。这是敏感性范围，不是已知延迟界，也不是挑选延迟拟合结果。
- 首段与末段窗口平均水平误差约 4.0 cm / 4.6 cm，未显示随运动持续增长的大幅误差，但短距离单次测试不能证明没有长期漂移。

必须区分三个问题：

1. 地图定位误差：算法给出的机身位置，与实际机身位置相差多少。本报告检查这一项。
2. 路径跟踪误差：机器狗实际是否沿局部规划曲线运动。之前约 24 cm 的原地转向平移是物理运动偏差，不能直接当作地图定位漂移。
3. FAST-LIO 单独的累计漂移：当前记录没有足够的独立、带原始时间戳的 LIO 位姿来严格分离计算，不能拿融合后的地图定位误差代替它。

另一个独立问题仍未修复：初值较大错误时，初始化可能错误接受，并在错误的地图位置附近持续跟踪。稳定 tracking 不等于正确定位。
